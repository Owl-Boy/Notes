# Inductive Types
---
An inductive type is meant to be a type that is freely generated by a finite collection of functions (which can have 0 inputs) whose codomain is the type. For example
- The [[Product Type|Unit Type]] is generated by a single constructor $\star$.
- The [[Product Type]] $A \times B$ is generated by the constructor $(-,-) : A \to B \to A \times B$.
- The type of [[Natural Numbers in Type Theory|Natural Numbers]] is created by 2 constructors 
	- $0$, which is a value
	- $\text{suc}: \mathbb{N} \to \mathbb{N}$

And so on.
>[!note]
>The constructors are allowed to have the inductive type as their domain.

Another such type is $[A]$, which can be defined as 
$$
\begin{align}
\square &: [A] \\
(- :: - ) &: A \to [A] \to [A] 
\end{align}
$$
These inductive types are meant to be *Freely generated* and that is expressed using their elimination rule, or the induction principle.

>[!example]
>For example the induction principle for the type $\mathbf{2}$:
>- When proving a statement $E:\mathbf{2} \to \cal U$, it suffices to prove it for $0$ and $1$.
>
>Thus there is a function $\text{ind}_{\mathbf{2}}$, that takes a type family $E:\mathbf{2}\to\cal U$, then $e_{0}:E(0)$ then $e_{1}:E(1)$, then we get $\text{ind}_{\mathbf{2}}(E,e_{0},e_{1}):\prod_{x:\mathbf{2}}E(x)$ such that:
>$$
>\begin{align}
>\text{ind}_{\mathbf{2}}(E, e_{0}, e_{1},0) :\equiv e_{0}\\
>\text{ind}_{\mathbf{2}}(E, e_{0}, e_{1},1) :\equiv e_{1}
>\end{align}
>$$ 
>We usually call this case analysis.
